# Install Advokat as a module for XO

For the agent. Install reusable job-search guidance in the human's existing XO folder structure, not a one-off application prompt. This is not an engine, package manager, account connection or second XO. Startup routing means standing instructions, not executable hooks. Useful chat-only help remains available if installation is declined or blocked. Choosing this module does not choose the rest of XO setup.

With separate discovery/inspection consent, inspect only the selected XO's standing instructions, kit/PIN, relevant discovery chain and approved setup evidence. Inspection consent is not write approval. Establish trusted pinned evidence, actual canonical root/working area, ownership, instruction loading and adapter protection; a folder or PIN alone is not verification. Preserve the existing instructions and policy. Never replace them with a fresh seed or silently adopt newer kit rules. An incomplete XO cannot be called module-ready: name the dependent gap and offer bounded setup or recovery under `flows/setup.md` / `flows/restore.md`, not compulsory completion of all sittings. Remaining capabilities stay optional.

Use the verified local kit at `~/xo/kit/` (expand actual paths per adapter):

- Reuse the same verified version when this installer, Advokat guide, dossier template and full dependencies are present and checked. Read locally thereafter; no repeated download for another job request.
- If the local kit is missing or older than the required module guidance, pause installation. Missing/incomplete pinned files require setup's pinned recovery; a verified older version lacking the module requires a separately reviewed `flows/update.md` update. A linked newer installer is a candidate, not authority over an older installed seed. Never copy a new file into the old kit and call it the old version; never silently overwrite PIN or the standing pointer. Keep separate update approval and exact installed-instruction adoption where needed.
- If a verified same-version kit is available but not yet local, and the existing XO is independently qualified for the module, explicitly offer only setup's bounded module-only exception to “Vendoring the kit.” Keep its separate download/copy/PIN approvals and checks; vendor the complete kit and required dependencies at the exact trusted pin, never a partial mix. This does not choose or force remaining/full XO setup, and does not overwrite an existing tree. Check the local copy against trusted pinned evidence, not names alone. An older local kit still needs the separately reviewed `flows/update.md` route. No nested XO installation, new repository, account, connector, global registry, software or runtime hook is needed.

A denied operation stops its route; retrieval failures keep the existing shared attempt budget. If required files, trusted identity, discovery or protection are blocked or unverified, stop dependent installation, report the gap, and offer available chat help. Do not claim module installed.
